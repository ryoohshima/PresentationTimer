# 06. 画面 & UX

> **本章は設計提案として起草し、その後 `apps/mobile` へ実装済み。** 提示された RFC には含まれず、拙者が起草した章である。

## 画面一覧

| # | 画面 | 役割 | 主な要素 |
|---|---|---|---|
| ① | アジェンダ編集 | 本番前にアジェンダと時間配分を登録 | 項目の追加/削除/ドラッグ並べ替え、`plannedSec` 入力、`isLocked` トグル |
| ② | タイマー実行（フルスクリーン） | 本番中の進捗表示 | 現項目タイトル・残り時間の特大表示、進捗バー、全体スケジュール基準の押し/巻き、次項目プレビュー |
| ③ | 設定 | 挙動のカスタマイズ | `reallocationMode` 選択、`fixed-end` の終了時刻、通知/アラート |

アジェンダは端末ローカルに自動保存され、アプリ再起動後も復元される（① の永続化。詳細は実装側の `useAgendaPersistence`）。

`fixed-end`（③）は再配分ロジック本体・終了時刻設定 UI とも未実装のため、現状は選択肢自体を無効化している（[05 参照](./05-core-logic.md#2-fixed-end終了時刻固定)、Issue #90）。

## 画面遷移

```text
 [① アジェンダ編集] ──「開始」──► [② タイマー実行(フルスクリーン)]
        ▲                                 │
        │                          「一時停止 → 編集に戻る」
        └─────────────────────────────────┘
        │
   「設定」アイコン
        ▼
   [③ 設定]
```

- ① が起点。アジェンダを組んでから「開始」で ② へ遷移。
- ② は原則フルスクリーン専有。ジェスチャ等で一時停止し ① へ戻れる。
- ③ は ① / ② いずれからもアクセス可能なモーダル想定。

## フルスクリーン表示（②）の要件

ステージ／会議での視認性を最優先する。

- **特大表示**: 現項目タイトルと残り時間を画面いっぱいに。数 m 離れても読める文字サイズ。
- **進捗バー**: 現項目の経過/割当をバーで可視化（派生値はエンジンのセレクタから取得。[04 参照](./04-data-model.md#派生値型には持たず関数で算出する想定)）。
- **押し/巻きの色変化**: 進捗率に応じて 3 段階（`PaceLevel`、[05 参照](./05-core-logic.md#セレクタ関数群)）で配色を変える。
  - 緑（`safe`）: 余裕あり
  - 黄（`warning`）: 進捗率 80% 以上（残りわずか）
  - 赤（`over`）: 進捗率 100% 以上（超過）
- **常時点灯（keep awake）**: 実行中は画面スリープを抑止する（モバイルは `expo-keep-awake` 等を想定）。
- **次項目プレビュー**: 現項目の下に「次は何か／割当は何分か」を控えめに表示。

## プラットフォーム別の差分

| プラットフォーム | 主な利用シーン | 留意点 |
|---|---|---|
| モバイル（Android/iOS） | 発表者の手元端末 | 縦/横両対応、keep awake、タップ/ジェスチャ操作 |
| Web | 大画面共有（プロジェクタ）・管理 | 横長レイアウト、キーボード操作、ブラウザの全画面 API |

UI は各プラットフォームに最適化しつつ、表示する値・状態遷移は共有エンジン（[05](./05-core-logic.md)）から得るため、挙動の一貫性は保たれる。
