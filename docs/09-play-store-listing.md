## 詳しい説明（4000 字以内）

```
プレゼンタイマーは、発表・登壇・会議の進行のための「アジェンダ登録型」タイマーアプリです。

事前にアジェンダ（進行項目）と時間配分を登録しておけば、本番中はスマホの画面いっぱいに「いま何の時間か」「あと何分か」を特大表示。数メートル離れた場所からでもひと目で進行状況を確認できます。

■ こんな場面で
・カンファレンスや LT での登壇
・時間厳守の社内プレゼン、報告会
・複数の議題を順番にこなす会議のファシリテーション
・発表練習のセルフチェック

■ 主な機能
【アジェンダ登録】
項目の追加・削除・ドラッグでの並べ替えに対応。各項目に予定時間を割り当てるだけで準備完了。アジェンダは端末に自動保存され、アプリを閉じても消えません。

【全画面タイマー表示】
本番中は現在の項目名と残り時間を画面いっぱいに表示。進捗バーと 3 段階の色分け（余裕あり／残りわずか／超過）で、遠目にも進行状況が伝わります。実行中は画面が自動でスリープしません。

【押し・巻きの自動再配分】
このアプリの最大の特長です。ある項目が予定より長引いても（押し）、早く終わっても（巻き）、残りの項目へ自動で時間を再配分。「1 つ押したせいで後の計算が狂う」ストレスから解放されます。時間を動かしたくない項目はロックして固定できます。

【次項目プレビュー】
現在の項目の下に「次は何を何分で話すか」を控えめに表示。頭の切り替えがスムーズになります。

■ 安心して使えます
・アカウント登録は不要。起動してすぐ使えます
・入力したアジェンダは端末内にのみ保存され、外部に送信されません

発表の残り時間を気にして時計とアジェンダを交互に見る時代は終わりです。プレゼンタイマーに進行管理を任せて、話すことに集中してください。
```

（約 700 字。上限 4000 字に対し十分な余裕あり）

## データセーフティ申告（回答案）

実装の実態（PR #120 時点で確認済み: 解析 SDK・広告 SDK・外部通信なし、AsyncStorage による端末内保存のみ）に基づく。

| 質問 | 回答 |
|---|---|
| データを収集しますか | **いいえ** |
| データを第三者と共有しますか | **いいえ** |
| データは転送中に暗号化されますか | 該当なし（収集なしのため設問自体が出ない） |

### 広告導入時の連動更新

ディスプレイ広告（AdMob 等）を導入する際は、以下をすべて同一リリースで更新する。**虚偽申告はアプリ削除の対象**であり、1 つでも取り残すと違反になる。

| 対象 | 現在 | 広告導入後 |
|---|---|---|
| データセーフティ申告 | 収集なし | **収集あり**。広告 ID・デバイス識別子・おおよその位置情報など、導入する SDK の実際の収集項目を申告 |
| 広告の有無申告 | 広告を含まない | 広告を含む |
| 広告 ID（AD_ID）の申告 | いいえ | **はい**。未変更のままだとリリースがブロックされる。`com.google.android.gms.permission.AD_ID` 権限は Google Mobile Ads SDK のライブラリマニフェストから自動マージされるため、`app.json` への明示的な権限追加は不要 |
| コンテンツレーティング | 全年齢（質問票すべて「なし」） | 質問票を再回答 |
| プライバシーポリシー | 「現時点でアクセス解析ツールおよび広告配信 SDK を組み込んでいません」 | 導入する SDK・収集項目・オプトアウト方法を明記して改訂 |

> 詳しい説明の「入力したアジェンダは端末内にのみ保存され、外部に送信されません」は主語がアジェンダに限定されているため、広告導入後も真であり変更不要。
> 一方「広告や解析ツールは含まれていません」はアプリ全体への断定で導入と同時に偽になるため、初回申請の掲載文からあらかじめ除外してある。

> 注意: 解析・クラッシュレポート等の SDK を導入する場合も同様に、この申告とプライバシーポリシーの両方を必ず更新すること。

## 提出までのフロー（個人アカウントの制約）

新規個人デベロッパーアカウントは、製品版公開の前に **「12 人以上のテスターが継続 14 日間」のクローズドテスト** が必須（[Play Console ヘルプ](https://support.google.com/googleplay/android-developer/answer/14151465?hl=ja)）。

1. 開発者アカウント登録（25 USD）→ 承認待ち
2. アプリ作成 → 本書の掲載情報・データセーフティ・レーティングを入力
3. aab をクローズドテストトラックへアップロード（Issue #30 の成果物）
4. テスター 12 人を招集（Web 参加リンクを使用）→ 継続 14 日間
5. 製品版アクセス申請 → 承認後、製品版リリース作成 → 審査提出（Issue #31 完了）
