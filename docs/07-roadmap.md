# 07. ロードマップ

> **本章は設計提案である。** 提示された RFC には含まれず、拙者が起草した。実装フェーズの検証や優先度判断により変更されうる。

機能を段階的に提供する。各フェーズは「単独で価値が出る最小単位」を意識して区切る。

## 現在の実装状況（概況）

- **MVP**: 中核体験（アジェンダ編集・ドラッグ並べ替え・単一端末フルスクリーン実行・`proportional` 再配分・押し/巻きの色変化・進捗バー・keep awake・アジェンダの端末永続化）は `apps/mobile` に実装済み。
- **Phase 2**: 設定画面（③）自体は先行実装済みだが、`fixed-end` モードは再配分ロジック本体・終了時刻設定 UI とも未実装で選択肢を無効化中（[05](./05-core-logic.md#2-fixed-end終了時刻固定)、Issue #90）。iOS は Expo の共有コードで技術的には動作するが、配布（審査・アセット等）は未着手。
- **Phase 3**: `apps/web` はサンプルデータを表示するだけの PoC 段階で、大画面共有・端末間同期は未着手。

進行中の Issue は流動的なため、最新状況は [GitHub Issue](https://github.com/ryoohshima/AgendaTimer/issues) を参照すること（本章に個別 Issue 番号は転記しない）。

## MVP（最小実用版）

Android を先行ターゲットとし、本アプリの中核体験を最短で検証する。

- アジェンダ編集（項目の追加/削除/並べ替え、`plannedSec` 入力）
- 単一端末でのフルスクリーンタイマー実行
- **`proportional`（比例再配分）** モードのみ
- 押し/巻きの色変化・進捗バー・keep awake

> ゴール: 「事前登録 → フルスクリーン進捗 → 自動再配分」という [01](./01-overview.md) で定義した狙う体験を、最小構成で成立させる。

> 📋 **本 MVP の各ステップは GitHub Issue として起票済み。** ラベル（`claude-code` / `needs-human` / `blocker` / `standalone`）の定義と運用方針は [08. 実装ラベルの運用](./08-implementation-issues.md) を参照。

## Phase 2（再配分とカスタマイズの拡充）

- **`fixed-end`（終了時刻固定）** モードの追加（現状は未実装・選択肢を無効化中）
- 設定画面（[06 ③](./06-screens.md#画面一覧)）の実装（画面自体は実装済み。`fixed-end` 関連 UI は準備中）
- 項目ロック（`isLocked`）の UI 対応
- iOS 提供（Expo の共有コードで展開。配布作業は未着手）

## Phase 3（マルチチャンネル & 同期）

- **Web 大画面共有**（`apps/web`）の本格提供
- 端末間同期（発表者端末 ↔ 大画面）
- テーマ／配色カスタマイズ
- アジェンダのテンプレート保存・再利用

## スコープ外（初期は作らない）

過剰実装を避けるため、当面は対象外とするものを明示する。

- クラウドアカウント・ログイン基盤
- 複数ユーザーでの共同編集
- 録画・分析ダッシュボード
- 課金/サブスクリプション

## フェーズと再配分モードの対応

| フェーズ | `proportional` | `fixed-end` | `off` | プラットフォーム |
|---|---|---|---|---|
| MVP | ✅ | – | ✅ | Android |
| Phase 2 | ✅ | ✅ | ✅ | + iOS |
| Phase 3 | ✅ | ✅ | ✅ | + Web |

> `off` は再配分をしないだけの単純なモードのため MVP の実装（`redistribute` のモード分岐）に含めて先行提供済み。
